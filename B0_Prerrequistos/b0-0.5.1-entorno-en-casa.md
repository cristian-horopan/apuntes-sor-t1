* # Qué se pedía Dejar mi ordenador de casa en el mismo estado que el del centro: 
* instalar las herramientas, crear una clave SSH propia para este equipo y reconstruir mi bóveda de Obsidian clonando mis repositorios desde GitHub, sin copiar nada con pendrive. 
* # ⌨️ Comandos y pasos importantes 
* `ssh-keygen -t ed25519 -C "correo"` — crea la clave SSH del equipo (pública y privada). 
* `cat ~/.ssh/id_ed25519.pub` — muestra la clave pública para pegarla en GitHub. * `git config --global user.name` / `user.email` — configura mi identidad en Git. * `ssh -T git@github.com` — comprueba que GitHub me reconoce por SSH. * `mkdir -p ~/Documentos/SOR/Boveda_SOR/00_Apuntes` (y `01_Practicas`) — crea la estructura de la bóveda, fuera de OneDrive. 
* `git clone git@github.com:USUARIO/apuntes-sor-t1.git Trimestre_1` — clona los apuntes con el nombre de carpeta correcto. * `git clone ... B0_Prerrequisitos`, `B1_Entorno` y `B2_Ubuntu_Local` — clona los tres repos de prácticas. 
* # Qué he hecho 
1. Inicié la grabación con OBS y abrí Git Bash. 
2. Generé la clave SSH con `ssh-keygen`. Me avisó de que ya existía una clave y me preguntó si la sobrescribía. 
3. Mostré la clave pública con `cat` y la añadí en GitHub (Settings → SSH and GPG keys → New SSH key). 
4. Comprobé en la lista de claves de GitHub que seguía teniendo la de Equipo Centro y la de casa. 
5. Configuré `user.name` y `user.email` en Git.

9. Detuve la grabación.
# Qué me ha fallado y cómo lo he resuelto 
* Al mostrar la clave pública con `cat`, la primera vez salió: `cat: /c/Users/crihor2/.ssh./id_ed25519.pub: No such file or directory`. 
* Hice `git push` estando en `01_Practicas` y salió: `fatal: not a git repository (or any of the parent directories): .git`. Esa carpeta no es un repositorio; cada repo está dentro de su subcarpeta, y el push hay que hacerlo desde dentro de una de ellas. 
* # Respuestas a las preguntas 
1. ¿Por qué clonas desde GitHub en vez de copiar con pendrive? Porque la versión buena está en GitHub. Si copio con pendrive puedo llevarme una versión antigua, y clonando la copia de casa es idéntica a la del centro.
2. ¿Por qué generas una clave SSH nueva en casa? Porque la clave privada no se copia de un equipo a otro. Cada equipo tiene la suya y se añade a GitHub; es normal tener varias.
3. ¿Dónde NO debe estar la bóveda? En una carpeta sincronizada con OneDrive, porque Git y OneDrive se pelean (aparecen ficheros duplicados tipo `...-MiPC.md`). Mi "nube" es GitHub.
